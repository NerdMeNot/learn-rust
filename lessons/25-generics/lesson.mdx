## Generic functions

A **generic** function is written once with a placeholder for a type, usually `T`, and the compiler fills it in at each call. [Reading signatures](/learn/reading-signatures/) shows where the `<T>` goes; this lesson is about what it does.

<Snippet file="generic-fn.rs" />

- `T` is worked out from the arguments. `&[4, 8, 15, 16]` makes it `i32`, and the words make it `&str`.
- It returns references into the slice, not `T` itself: a generic `T` may not be `Copy`, and moving an item out of a slice is refused ([Reading signatures](/learn/reading-signatures/) runs E0508).
- An empty list says nothing about `T`, so `first_and_last::<f64>(&[])` names it with the turbofish ([`::<>`](/learn/declarations-types/#as-and-the-turbofish)).
- `T: Default` is a **bound**: "`T` must have a default value". Bounds get their own section below.

`zero` mentions `T` only in its result, so a call with nothing to go on is an error:

<Snippet file="return-only.fail.rs" />

`help:` offers a type on the `let`; `zero::<i32>()` does the same job. This is E0283. `Vec::new()` with no use gave E0282 in [Declarations and types](/learn/declarations-types/#the-type-is-often-optional); both are the "type annotations needed" family.

## Generic structs and enums

Structs and enums take type parameters the same way. `Vec<T>`, `Option<T>` and `Result<T, E>` are ordinary types declared like this, and `Maybe<T>` below has the shape of `Option<T>`.

<Snippet file="generic-types.rs" />

- In `impl<T> Pair<T>`, the first `<T>` introduces the placeholder and the second says which type the block is for.
- A method can add parameters of its own after its name: `map<U>` turns a `Pair<T>` into a `Pair<U>`, and `impl Fn(T) -> U` takes a [closure](/learn/closures/).
- `impl Pair<f64>` names one concrete type, so `sum` exists only for pairs of `f64`.
- `Entry<K, V>` has two parameters, the same type or different ones.

## Bounds: what `T` may do

Inside a generic body, `T` could be any type, so a bare `T` has no `{}`, no `==` and no `.clone()`: the body can move it, borrow it and store it. Anything more must be asked for in a **bound**, the name of a [trait](/learn/traits/) (an ability a type can have):

<Snippet file="bare-t.fail.rs" />

The `help:` writes the bound for you. These are the ones you will ask for most; [Common traits](/learn/common-traits/) says what each means.

| To do this with a `T` | Ask for |
|---|---|
| print with `{}`, with `{:?}` | `Display`, `Debug` |
| compare with `==`; with `<` and `>` | `PartialEq`; `PartialOrd` |
| `sort()`, `max()`, use as a `BTreeSet` item | `Ord` |
| use as a `HashMap` key or `HashSet` item | `Eq + Hash` |
| call `.clone()` | `Clone` |
| use a value twice without moving it | `Copy` |
| `a + b` giving a `T` | `Add<Output = T>` |
| `T::default()` | `Default` |
| turn a `u8` or `u32` into a `u64` | `Into<u64>` |

`f64` has `PartialOrd` but not `Ord`: `NaN` is neither less than nor greater than anything, so `sort()` on floats is refused ([Common traits](/learn/common-traits/#equality-order-and-hashing)). Leave a needed bound out and the error is inside the body; pass a type that lacks it and the error is at the call ([Reading signatures](/learn/reading-signatures/#the-bound-is-checked-where-you-write-it) shows both).

`a + b` is the odd row, and the [gotcha](#gotcha) above is about it. `T: Add` says two `T`s can be added, but the sum has a type of its own, `T::Output`, and for `&i32` it is `i32`:

<Snippet file="add-output.rs" />

`Add<Output = T>` closes the gap: "adding two `T`s gives a `T`".

## Methods for some `T` only

A bound can sit on an `impl` block, so its methods exist only for types that qualify:

<Snippet file="conditional-impl.rs" />

A list has no `show`; the error says a bound is missing and points at the `impl` that asks for it:

<Snippet file="conditional-impl.fail.rs" />

Put bounds on the `impl` that needs them, not on the struct. A bound on the struct is demanded of every `impl` that mentions it, even one whose methods do not use it:

<Snippet file="struct-bound.fail.rs" />

The API Guidelines agree: [Data structures do not duplicate derived trait bounds](https://rust-lang.github.io/api-guidelines/future-proofing.html#c-struct-bounds).

The same works for a trait: `impl<T: Display> Shout for T` gives `Shout` to every type that meets the bound, types written later too. This blanket impl runs in [Traits](/learn/traits/#traits-for-types-you-did-not-write); `ToString` is one.

## Traits with their own parameters

A trait can take type parameters too, and one type can implement it once for each:

<Snippet file="generic-trait.rs" />

The type you ask for picks the impl.

<ForLang only="java">

Java refuses the same shape: one class cannot implement two parameterizations of one interface.

<Snippet file="two-args.fail.java" />

</ForLang>

<ForLang only="csharp">

C# allows it, as Rust does:

<Snippet file="two-args.cs" />

</ForLang>

A parameter can have a default. [`Add`](https://doc.rust-lang.org/std/ops/trait.Add.html) is `Add<Rhs = Self>`, so `impl Add for Meters` means `Add<Meters>`, and a bare `T: Add` means `Add<T>`, which is why the gotcha can add two `T`s.

<Snippet file="default-param.rs" />

When a type should have only one answer, a trait uses an associated type instead, as `Add` does for `Output` and `Iterator` does for `Item` ([Traits](/learn/traits/#associated-types-and-constants)).

## Const generics

A **const generic** is a number, not a type, known when the program is compiled. It is how a function or type works with arrays of any length:

<Snippet file="const-generic.rs" />

`[i32; 3]` and `[i32; 4]` are different types, so `sum` takes the length as a parameter. `N` can be used as a value inside, and `0` is allowed. A const parameter may be an integer, `char` or `bool` (Reference). For a length known only at run time, use a slice or a `Vec` ([Vectors](/learn/vectors/)).

## One copy per type

The compiler writes a separate copy of a generic function for each type it is used with. This is called **monomorphization**. Each copy knows its `T`: `size_of::<T>()` is a plain number in it, and `<` or `+` is the operation for that type, chosen when compiling. `type_name::<T>()` below is for diagnostics only: the standard library says its text is not specified.

<Snippet file="mono.rs" />

The last line compares the addresses of two instances of `largest`: different functions. The Book says the result runs as if you had written each copy by hand ([Performance of Code Using Generics](https://doc.rust-lang.org/book/ch10-01-syntax.html#performance-of-code-using-generics)). The price is more compiled code, one copy per type. This page measures no speed, binary size or compile time, and the runner builds only debug builds.

Because a copy knows its `T`, a generic struct stores its fields inline:

## `T` has a known size, unless you say otherwise

Each copy must know how big its `T` is, so every type parameter carries a hidden bound, `Sized`. The text behind a `&str` is a `str`, whose length is known only when the program runs, so it cannot be a `T`:

<Snippet file="sized.fail.rs" />

`?Sized` ("may or may not have a known size") lifts the rule. A `&` has a known size, so a reference to the value is fine:

<Snippet file="sized.rs" />

You will meet `T: ?Sized` in standard library signatures: [`ToString`](https://doc.rust-lang.org/std/string/trait.ToString.html) is implemented for every `T: Display + ?Sized`.

## What `T` is at run time, in your language

In Rust each copy is for one concrete type, so no generic code is left at run time and there is no reflection on `T`: you cannot list its members or rely on its name. You can ask whether two types are the same, for `'static` types (types that hold no borrowed data), and you call `T`'s behaviour through trait functions such as `T::default()`:

<Snippet file="type-id.rs" />

Other languages keep more or less of `T`:

<ForLang only="go">

<Snippet file="runtime-type.go" />

Go makes one copy per *GC shape*, not per type: types that look the same to the garbage collector, such as all pointers, share one, with a dictionary of type information ([design note](https://github.com/golang/proposal/blob/master/design/generics-implementation-gcshape.md)). `Id[*int]` and `Id[*string]` run the same code; `Id[int]` and `Id[int64]` do not:

## When to make something generic

Write the concrete version first. Make it generic when a second type needs the same code, and ask for only the bounds the body uses: every extra bound narrows who can call it, as the exercises check.

## Generics or trait objects

A generic parameter is one type per use. `Vec<T>` holds only `T`s, and a list of mixed types is refused:

<Snippet file="one-type.fail.rs" />

When one list must hold different types that share an ability, you use a **trait object** (`dyn Trait`): the compiler no longer picks a copy, and the method is looked up while the program runs. [Trait objects](/learn/trait-objects/) covers it, and what it costs compared with generics.

<ForLang only="python typescript">

Your own answer to a mixed list is a union (`list[int | str]`, `(number | string)[]`). For a fixed set of types the Rust counterpart is an enum, not a trait object ([Traits](/learn/traits/#a-trait-or-an-enum)).

</ForLang>
