<p class="lr-layer" id="layer-toolkit">The toolkit</p>

Rust has three loops: `for` goes through a sequence of values, `while` repeats while a `bool` condition holds, and `loop` repeats until a `break`. `while let` is a `while` that tests a pattern. There is no three-part `for` and no `do ... while` ([what replaces them](/learn/what-rust-lacks/#operators-and-loops)). Outputs come from Linux on 64-bit ARM with Rust 1.99.1.

| Loop | Use it when | Its value |
|---|---|---|
| `for x in seq { }` | you have a range, an array or another sequence | `()` |
| `while cond { }` | a `bool` decides whether to go again | `()` |
| `while let Some(x) = expr { }` | you keep taking items until none is left | `()` |
| `loop { }` | there is no natural condition; you leave with `break` | whatever follows `break` |

Only `loop` can `break` with a value (`let x = loop { break 5; };`). [Statements and expressions](/learn/statements-expressions/#if-without-else-and-loops-that-give-a-value) shows the error `for` and `while` give if you try.

## Ranges

A **range** is a value that stands for a run of numbers (or `char`s): `a..b` stops before `b` and `a..=b` includes it. The end is read once, when the loop starts.

The trap is `4..0`: it is not a countdown. It is empty, so the body never runs, with no error. `rev` and `step_by` are methods on the range ([Iterators](/learn/iterators/)); wrap the range in parentheses before calling one. `step_by` counts from the front of whatever it receives, so order matters.

## The loop variable

The name after `for` is a new variable on every pass, and it belongs to the loop. It cannot be assigned unless you write `mut`, and even then only that pass sees the change. Python's `for` and TypeScript's `for...of` work the same way; the three-part `for` of C, Java, C#, Go and TypeScript keeps one counter that the body can change.

## `loop`, `break` and `continue`

`break` leaves the loop. `continue` skips the rest of this pass. In a `loop`, `break value` makes the whole loop evaluate to that value, so the result can be a plain `let` instead of a `mut` variable. A `loop` with the test at the end runs the body first, as `do ... while` does elsewhere:

## Labels

A name written `'outer:` in front of a loop lets `break 'outer` and `continue 'outer` act on that loop from inside an inner one. ## `while let`

`while let PATTERN = expr` runs the body while the pattern fits, and stops the first time it does not. ## Your language, in Rust

<ForLang only="go" title="What you write today">

| In Go | In Rust |
|---|---|
| `for i := 0; i < n; i++ {}` and `for i := range n {}` | `for i in 0..n { }` |
| `for i := 0; i < n; i += 2 {}` | `for i in (0..n).step_by(2) { }` |
| `for i := n - 1; i >= 0; i-- {}` | `for i in (0..n).rev() { }` |
| `for cond {}` | `while cond { }` |
| `for {}` | `loop { }` |
| `for i, v := range xs {}` | `for (i, v) in xs.iter().enumerate() { }` |
| `for _, v := range xs {}` | `for v in &xs { }` ([Looping Over a Collection](/learn/for-collections/)) |
| `outer:` ... `break outer`, `continue outer` | `'outer:` ... `break 'outer`, `continue 'outer` |
| `break` inside a `switch` leaves the `switch` | `break` inside a `match` leaves the loop |

## What `for` does

The [Reference](https://doc.rust-lang.org/reference/expressions/loop-expr.html#iterator-loops) says `for` calls `IntoIterator::into_iter` on the expression and then calls `next()` in a `loop`, leaving at `None`. That is why anything that produces items works, and why a range is an ordinary value rather than special loop syntax (`IntoIterator` is a trait, a set of abilities; [Traits](/learn/traits/)).
