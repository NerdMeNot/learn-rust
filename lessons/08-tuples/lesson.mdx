<p class="lr-layer">The toolkit</p>

A **tuple** groups a fixed number of values (its **slots**; the std docs say elements), and each slot can have its own type. Rust has no special syntax for returning several values: a function returns one tuple, and the caller unpacks it. Outputs come from Linux on 64-bit ARM with Rust 1.99.1.

## A tuple has numbered slots

The type is written like the value: `(i32, &str, bool)`. You read a slot with a dot and a literal number, `t.0`, `t.1` ([Declarations and Types](/learn/declarations-types/#the-pieces-in-one-table)).

<Snippet file="basics.rs" />

The slots sit inside the variable: `(i32, i32)` is 8 bytes, just the two numbers. `(u8, u32)` is 8 too, not 5, because the compiler adds padding for alignment and the language lets it reorder slots. The [layout of a tuple is not promised](https://doc.rust-lang.org/reference/type-layout.html); the sizes are what this compiler printed.

A tuple is not a list. `t[0]` is refused because the slot has to be a literal, so the compiler knows its type. A `for` loop is refused because the slots can have different types, so there is no single type for `x`:

<Snippet file="tuple-loop.fail.rs" />

| | Tuple `(A, B)` | Array `[T; N]` | `Vec<T>` |
|---|---|---|---|
| Types of the slots | each its own | all the same | all the same |
| Length | fixed, part of the type | fixed, part of the type | grows |
| Read a slot | `t.0`, a literal only | `a[i]`, any `usize` | `v[i]` |

## Unpacking

`let (q, r) = ...` is a **pattern** ([patterns in `let`](/learn/declarations-types/#patterns-in-let-and-shadowing)): it has the shape of the value and names its parts (Python calls this unpacking; Kotlin, C# and JavaScript, destructuring). ## A missing pair, a failed pair

A pair that might not exist is an `Option<(A, B)>`, and one that might fail is a `Result<(A, B), E>`: the tuple goes inside. `str::split_once` returns the first kind. [Option](/learn/option/) and [Errors](/learn/errors/) teach how to open them. The type records that the value may be missing, so you cannot reach it without deciding what to do about `None` or `Err`. That is why a Go `(value, err)` pair is a `Result` in Rust, not a tuple of two values.

## Comparing tuples

Tuples compare slot by slot, left to right: the first slot that differs decides, and later slots only break ties (the std docs say this for `PartialOrd` and `Ord`). `==` compares slot by slot too. That makes a list of tuples sortable, and a tuple a usable [map key](/learn/maps/#keys-need-hash-and-eq) when its parts are (`check-rows.rs` runs one):

## Tuple or struct?

A tuple does not say what its slots mean. When both slots have the same type, the compiler cannot catch a swapped pair:

<Snippet file="vs-struct.rs" />

`aspect((9, 16))` compiles and gives a different answer. A [struct](/learn/structs/) names the fields, so a caller writes `width: 16` and cannot mix them up.

| Reach for a tuple when | Reach for a struct when |
|---|---|
| the result is short-lived and the caller unpacks it at once | the value is stored, passed around or returned from a public API |
| the slots have different types, so mixing them up does not compile | two slots share a type, or the slots keep growing in number |

## Tuples stop at twelve, for the standard traits

Any length is a legal tuple type. But the traits that give a tuple `{:?}` printing, `==`, ordering, a default value and hashing (`Debug`, `PartialEq`, `PartialOrd`, `Ord`, `Eq`, `Default`, `Hash`; see [Traits](/learn/traits/)) are implemented only up to 12 slots. The std docs call it a "temporary restriction in Rust's type system" that "may change". `Clone` and `Copy` have no limit:
