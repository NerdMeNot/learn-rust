## An enum is one of a fixed list

An `enum` (short for enumeration) is a type whose value is exactly one of a list of names, called **variants**. You write the list once. The compiler then knows every value the type can hold, which is what lets it check your code.

<Snippet file="plain.rs" />

- A variant is written `Direction::North`: the enum's name, `::`, the variant's name.
- `match` takes a value apart by variant ([match lesson](/learn/match/)).
- `#[derive(Debug)]` lets `{:?}` print the value. More on `derive` [below](#derive-on-enums).

## Variants that carry data

This is where Rust enums go further than the enums in most languages. Each variant can hold its own data, and different variants can hold different things.

<Snippet file="data-variants.rs" />

There are three shapes of variant, and one enum can mix them:

| Shape | Written | Fields are reached by |
|---|---|---|
| No data | `Quit` | nothing to reach |
| Tuple-like | `Paint(u8, u8, u8)` | position: `Command::Paint(r, g, b)` |
| Struct-like | `Move { x: i32, y: i32 }` | name: `Command::Move { x, y }` |

A value is exactly one variant at a time. A `Command` is never a `Say` and a `Move` together, and you cannot read `x` from a `Say`. `match` is how you ask which one you have, and it hands you the data in the same step.

## `match` must cover every variant

Leave a variant out and the program does not compile:

<Snippet file="missing-variant.fail.rs" />

The error is E0004. It names the missing case, points at the variant, and suggests an arm. When you add a variant to an enum later, every `match` that forgot it fails the same way. The compiler gives you a to-do list of places to update.

Patterns can look inside variants:

<Snippet file="patterns.rs" />

- A guard (`if radius == 0.0`) adds a condition to an arm. Arms are tried from the top, so put the specific ones first.
- `height: 1.0` inside a pattern requires that field to equal the value.
- `..` ignores the fields you do not name.

### Matching through a reference

The functions above take `&Shape`, so `match` gives you **references to the fields**. In `Shape::Circle(r)` below, `r` is a `&f64`, which is why `patterns.rs` wrote `*radius == 0.0` in a guard. Arithmetic and comparing two references work as they are, and `*` follows a reference to the number when you need the number itself.

<Snippet file="match-ref.rs" />

Matching a value you only borrow, and trying to take something out of it, is the most common first error with enums:

<Snippet file="move-out.fail.rs" />

`match self.job` tries to move the `String` out of a `&self`, and E0507 refuses. Match on `&self.job` and clone what you need (`msg.clone()`), or take `self` by value as the state machine below does.

## `if let`, `let else` and `matches!`

When you care about one variant, a full `match` is a lot of text.

<Snippet file="if-let.rs" />

- `if let PATTERN = value { … }` runs the block only if the pattern fits. `else` is optional.
- `let PATTERN = value else { … };` binds the names for the rest of the block. The `else` block must leave (`return`, `break`, `continue` or a panic), so the happy path stays unindented.
- `matches!(value, PATTERN)` is a `bool`. It binds nothing.

These do not check that you covered everything, so use `match` when every case matters.

## State machines: make illegal states hard to write

Many programs track a thing that moves through stages: a job, an order, a connection. A common first model is one struct whose fields cover every stage:

<Snippet file="job-record.rs" />

Nothing stops "running and done" or a `percent` of 250 on a job that failed. Every function that reads the struct has to guard against nonsense. An enum lists only the states that exist, and each state holds only its own data:

<Snippet file="state-machine.rs" />

- A `Waiting` job has no `percent`, because the field does not exist in that variant. A `Failed` job has its reason and nothing else. (A `percent` above 100 is still possible. A smaller type or a checked constructor would fix that.)
- Add a `Cancelled` variant later, and every `match` on `Job` fails to compile until it says what `Cancelled` means.
- `next` takes `self` **by value**: it consumes the old state and returns the new one, so nobody keeps using a stale state ([Ownership](/learn/ownership/)). It is the `(state, event) -> state` shape of a reducer.
- Matching on the pair `(self, event)` makes the legal moves a table, one arm per row. The last arm ignores any other move: the first `Progress(50)` in the output, on a job that has not started, changed nothing. So the *states* cannot be wrong, but the *moves* are checked only by that arm. A later lesson shows returning a `Result` instead.

This is called "making illegal states unrepresentable".

## Enums with no data are numbers underneath

An enum whose variants hold no data is called C-like. Each variant has a number (its **discriminant**), starting at 0 and counting up, or the value you give it. `as` turns a variant into that number. Only enums where no variant holds data can be cast this way.

## `Option` and `Result` are enums

`Option` and `Result` are not special syntax. They are enums defined in the standard library, and you match them like yours:

<Snippet file="std-enums.rs" />

`Option<T>` is `Some(value)` or `None`: a value that may be missing. `Result<T, E>` is `Ok(value)` or `Err(error)`: an operation that may fail. `Maybe<T>` above is the same idea written by hand (`<T>` means "any type", covered in [Generics](/learn/generics/)). ## What an enum looks like in memory

Sizes on this page come from Linux on 64-bit ARM with Rust 1.99.1 (C is GCC 14, C++ is g++ 14). They depend on the machine: on a 32-bit target a `String` is 12 bytes. Where the language promises a size, the text says so.

A variable of an enum type has room for the biggest variant's data and, usually, a **tag** that says which variant is stored. The tag is the variant's discriminant, stored in the value. Every `Shape` is the same size, whether it holds a circle or a rectangle, because the type has to fit the biggest one.

<Snippet file="layout.rs" />

On this machine `Shape` is 24 bytes: a circle needs one `f64` (8 bytes), a rectangle two (16), and the tag is padded out to 8 so the `f64`s start at multiples of 8. `Plain`, with three variants and no data, is a single byte: only the tag. These are rustc's choices, because the [Reference](https://doc.rust-lang.org/reference/type-layout.html) leaves the default layout open. For a picture we ask for a fixed layout with `#[repr(u8)]`: a one-byte tag first, then the variant's fields. We can read the bytes:

<Snippet file="peek-tag.rs" />

([`unsafe`](/learn/unsafe/) means "the compiler cannot check this, I promise it is fine". Here it is needed only because we read raw bytes.)

`Command` holds a `String`, which is 24 bytes on its own, and `Command` is also 24 bytes on this machine. A `String` has no padding, so here the tag must live inside the `String`'s own bytes, in values a real `String` never has. That works only because the other variants (three `u8`s) fit in the remaining bytes. `Big`, with three `u64`s, is 32. Nothing in the language promises either result: the only sizes the standard library guarantees are the `Option` cases below.

<ForLang only="java kotlin csharp python typescript">

In your language a `Shape` variable holds a reference to an object (a record, class or dict), and an array of shapes is an array of references. A Rust `[Shape; N]` holds the shapes themselves, one after another in one block, with no object per element.

</ForLang>

<ForLang only="go">

A Go `[]Shape` holds interface values, which refer to the shapes. A Rust `[Shape; N]` holds the shapes themselves, one after another in one block.

</ForLang>

<ForLang only="c cpp">

This is the layout you write by hand for a tagged union. The C struct from the first program is the same size:

<Snippet file="tagged-size.c" />

The C++ `std::variant` is also 24 bytes. It keeps a tag too, and `std::get` checks it at run time:

<Snippet file="variant-get.cpp" />

In C, nothing checks the tag. If the code changes it, or forgets to, you read bytes as the wrong type:

<Snippet file="wrong-tag.c" />

## Niches: why `Option` is often free

A `u32` has no spare value to mean "none", so `Option<u32>` is 8 bytes. A reference is never null, so the value 0 is free to mean `None`. The compiler uses it, and the tag disappears. A free bit pattern like this is a **niche**.

<Snippet file="niche.rs" />

<Memory
  title="let value = 7u8;   let some = Some(&value);   let none: Option<&u8> = None;"
  stack={[
    { name: 'value', type: 'u8', cells: ['7'] },
    { name: 'some', type: 'Option<&u8>', cells: ['address of value'], toVar: 'value', note: 'a non-zero address means Some' },

  ]}
  caption="`Option<&u8>` is 8 bytes, the same as `&u8`. There is no separate tag. The program above printed it: `None` reads as 0 and `Some` as non-zero."
/>

The standard library [guarantees](https://doc.rust-lang.org/std/option/index.html#representation) this for `Option` of `Box<T>`, `&T`, `&mut T` (with `T` of known size), function pointers and the `NonZero` number types. Other types, such as `bool` and `String`, have niches too, as the output shows, but only the types in the docs are promised. `Option<&T>` is the safe replacement for a pointer that might be null, and it is the same size as the pointer.

<ForLang only="java kotlin">

On the JVM a `String?` or `Optional<String>` is already about as cheap as a reference, but an `Int?` or `Optional<Integer>` is an object. Rust's `Option<u32>` is a flat 8 bytes (printed above).

</ForLang>

## Recursive enums need `Box`

A tree is an enum that contains itself: an expression is a number, or two expressions added together. Written directly, the size has no end, because `Expr` would hold two `Expr`s, each holding two more:

<Snippet file="recursive.fail.rs" />

The fix is `Box<Expr>`. A `Box` is a pointer to a value on the heap (the pool of memory from [Stack and heap](/learn/stack-heap/)). The pointer has a fixed size, whatever it points at, so `Expr` has a size again. Boxes get a full lesson in [Smart pointers](/learn/smart-pointers/#boxt-one-owner-on-the-heap). For now you only need `Box::new(value)` to make one. A `&Box<Expr>` can be passed where a `&Expr` is expected, which is why `eval(a)` works below.

<Snippet file="recursive.rs" />

<ForLang only="java kotlin csharp python typescript">

In your language `record Add(Expr a, Expr b)` just works, because every object field is already a reference. Rust fields hold the value inline unless you add the `Box`.

</ForLang>

## How other languages handle this

<ForLang only="go">

Go has no sum types, so you build one from pieces. `iota` constants give you the names, but they are only integers. Any `int` is a `Color`, and the zero value of a `Color` is the first constant:

<Snippet file="iota.go" />

For data, Go's usual answer is a method on the interface. The compiler then checks every type you put in a `[]Shape`:

<Snippet file="interface-method.fail.go" />

The trade-off is open versus closed. With methods, a new shape is cheap, but a new operation touches every type. With an enum it is the other way round: a new operation is one new `match`, and a new variant makes the compiler list every `match` to update. Pick the enum when you control the whole list of cases and want that check. A type switch on an interface has neither benefit, as the gotcha at the top showed (an unexported method can close the interface to your package, but the switch is still unchecked).

</ForLang>

<ForLang only="python">

Python's `Enum` rejects a bad value at run time, which Go and C# do not:

<Snippet file="color-enum.py" />

Members can carry data, but every member has the same shape. For different data per case you use dataclasses and `match`, as in the first program. Python itself checks neither that the cases are complete nor the types of what a case holds. Type checkers can check some of it.

</ForLang>

<ForLang only="typescript">

A TypeScript numeric `enum` is a number, and a `number` is accepted where the enum is expected, so `42` becomes a `Color`. The usual alternative is a union of string literals or a discriminated union with a `kind` field ([narrowing](https://www.typescriptlang.org/docs/handbook/2/narrowing.html), including the `never` check):

<Snippet file="number-enum.ts" />

<Snippet file="json-tag.ts" />

In Rust the tag and the data are made together, so they cannot disagree. Turning JSON into an enum is a job for the `serde` crate, which checks the fields as it reads.

</ForLang>

<ForLang only="java">

A Java `enum` is a class with a fixed set of instances, which can have fields. A `switch` expression over it needs no `default`, and the compiler checks it. For data that differs per case you use [sealed types](https://openjdk.org/jeps/409) with records, as in the first program.

<Snippet file="enum-switch.java" />

Java's check has one gap Rust does not: it happens when the switch is compiled. If a new permitted type shows up in separately compiled code, the old switch throws a `MatchException` at run time ([JEP 441](https://openjdk.org/jeps/441) describes this). A Rust program is compiled from source together, so a stale `match` cannot exist.

</ForLang>

<ForLang only="kotlin">

A Kotlin `enum class` is mostly for named constants, and a `sealed class` is for cases that carry different data. Rust uses one construct for both. A `when` over a [sealed class](https://kotlinlang.org/docs/sealed-classes.html) is checked, like `match`, as the gotcha at the top showed. Each subclass is its own type (the program under "A variant is not a type" shows it), which a Rust variant is not.

</ForLang>

<ForLang only="csharp">

A C# `enum` is an integer in disguise. Any `int` can be cast to it, and nothing complains:

## Try it

Each exercise is a small program with checks in `main`. Open it in the Playground, replace the `todo!()`, and run it until it prints `all checks passed`.

<Exercise name="shape-area" title="Areas of shapes">
Fill in `area` for a circle, a rectangle and a triangle given by its three sides (Heron's formula). A set of sides that cannot make a triangle must give 0, not NaN.
</Exercise>

<Exercise name="door" title="A door with a lock">
Write the `apply` function for a door that is open, closed or locked with a code. Moves the rules do not allow, such as locking an open door or unlocking with the wrong code, leave the door as it is. `apply` takes the old door by value, so a `match` on the pair can hand it back.
</Exercise>

<Exercise name="expr" title="Evaluate and print an expression">
`Expr` is a tree of numbers, negations, sums and products. Write `eval`, which computes it, and `show`, which prints it with brackets. Both call themselves on the `Box`ed parts: pass `a` as it is, because a `&Box<Expr>` converts to `&Expr` by itself.
</Exercise>
