<p class="lr-layer">The toolkit</p>

Variables, constants, functions and types are declared with a keyword (`let`, `const`, `fn`, `struct`) and then a name. Where you write a type, it goes after the name, behind a colon. This page teaches only the spelling. The meaning is in the linked lessons: [Variables](/learn/variables/), [Numbers and types](/learn/types/), [Match](/learn/match/).

## The pieces in one table

| Syntax | What it is | Example | Learn more |
|---|---|---|---|
| `let`, `let mut` | A variable that cannot change, or can. | `let x = 5;` `let mut n = 0;` | [Variables](/learn/variables/) |
| `const` | A name for a value known before the program runs. | `const MAX: u32 = 99;` | [Reference](https://doc.rust-lang.org/reference/items/constant-items.html) |
| `static` | A value stored once for the whole program. | `static NAME: &str = "Ada";` | [Reference](https://doc.rust-lang.org/reference/items/static-items.html) |
| `fn` | A function. The result type follows `->`. | `fn add(a: i32, b: i32) -> i32` | [Functions](/learn/functions/) |
| `struct` | A record: named fields, or numbered. | `struct Point { x: i32 }` `struct Meters(f64);` | [Structs](/learn/structs/) |
| `enum` | One of several shapes. | `enum Shape { Circle(f64), Empty }` | [Enums](/learn/enums/) |
| `(A, B)` | A few values of different types. | `(7, "seven")`, `t.0` | [Tuples](/learn/tuples/) |
| `[T; N]`, `&[T]`, `Vec<T>` | A fixed-size array; a slice (a borrowed view of part of one); a growable list. | `[0u8; 4]`, `&v[1..4]`, `vec![1, 2]` | [Vectors](/learn/vectors/) |
| `a..b`, `a..=b` | A range, without and with the end. | `0..5`, `2..`, `..3` | [Loops](/learn/loops/) |
| `<T>` | Type arguments. | `Option<String>` | [Generics](/learn/generics/) |
| `\|x\| x + 1` | A closure: a function with no name. | `\|n\| n * 2` | [Closures](/learn/closures/) |
| `_` | "Ignore this part." | `let (a, _) = pair;` | [Reference](https://doc.rust-lang.org/reference/patterns.html#wildcard-pattern) |

## The type goes after the name

Read `count: i32` as "`count` is an `i32`". Rust does not convert between types for you: text is not a number, a whole number is not a float, and an `i32` is not an `i64`, even though it would fit.

<Snippet file="mismatch.fail.rs" />

Number types spell their kind and size. `i32` is a signed whole number in 32 bits, `u8` an unsigned one (zero and up) in 8 bits, `f64` a 64-bit float, and `usize` the unsigned type for lengths and indexes. An unsigned number cannot go below zero:

## Your language, side by side

<ForLang only="go">

| You write in Go | In Rust |
|---|---|
| `x := 5` | `let x = 5;`, or `let mut x = 5;` if you change it later |
| `var x int = 5` | `let x: i64 = 5;` Go's `int` is 64 bits on a 64-bit machine, Rust's default integer is `i32` |
| `var x int` (starts at 0) | `let x: i64;` has no value until you assign one ([below](#declared-now-set-later)) |
| `const Max = 100` | `const MAX: i64 = 100;` Rust has no untyped constants |
| `func add(a, b int) int` | `fn add(a: i64, b: i64) -> i64`: each parameter names its own type |
| `a, b := 1, "two"` | `let (a, b) = (1, "two");` A Go `(int, error)` result is a tuple in Rust ([Tuples](/learn/tuples/)) |
| `[]int{1, 2, 3}`, `string` | `vec![1, 2, 3]` and `&str`/`String`. A Rust slice `&[i64]` is a borrowed view; Go's slice is closer to a `Vec` |
| `float64(n)`, `int(f)` | `n as f64`, `f as i64`. Integer narrowing wraps in both. A float too big for the integer is implementation-dependent in Go ([spec](https://go.dev/ref/spec#Conversions)) and saturates in Rust |
| `017`, `0o17` | Only `0o17` is octal. `017` is the decimal number 17 |

## `as` and the turbofish

`as` converts between number types. It also turns a `char` or `bool` into an integer (not a float), and a `u8` into a `char`. It never fails at run time, which is why it can lose information silently:

<Snippet file="casts.rs" />

Integers that do not fit keep only their low bits (`big as u8` is 44 when `big` is 300, because a `u8` holds 0 to 255). The same bits can be read the other way: `200u8 as i8` is -56, because the top bit of a signed integer is its sign. Floats cut toward zero and saturate, stopping at the smallest or largest value, and `NaN` becomes 0. The standard library has `From` (`i64::from`) only for conversions that cannot lose data, and `u8::try_from(300)` returns an `Err` instead of cutting the value, as the last line shows.

A literal that does not fit is refused, not cut: `300 as u8` does not compile, because the `overflowing_literals` lint is deny by default. The `big as u8` above compiles, because `big` is a variable.

<Snippet file="cast-literal.fail.rs" />

A conversion that makes no sense is refused too:

<Snippet file="cast-char.fail.rs" />

<ForLang only="c cpp">

In C and C++ a float too big for the integer type is undefined behaviour ([cppreference](https://en.cppreference.com/w/cpp/language/implicit_conversion)). Rust's `as` saturates.

</ForLang>

The **turbofish** `::<T>` gives a type argument inside an expression, because `parse<i32>()` would read as comparisons. `unwrap` takes the number out of `parse`'s result and stops the program if the text was not one ([Errors](/learn/errors/) shows better handling). `_` in `Vec<_>` means "you work this part out", and `collect` gathers pieces into a list ([Iterators](/learn/iterators/)):

## Naming

Rust expects `snake_case` for values and `UpperCamelCase` for types. The compiler warns when you break this (the lints `non_snake_case`, `non_camel_case_types` and `non_upper_case_globals`, [listed here](https://doc.rust-lang.org/rustc/lints/listing/warn-by-default.html#non-snake-case)). `#![deny(nonstandard_style)]` at the top of a file (an "inner attribute", a setting for the whole file) turns all three into errors, which shows what the compiler thinks:

<Snippet file="naming.fail.rs" />

| What | Convention | Example |
|---|---|---|
| Variables, functions, methods, modules, fields | `snake_case` | `user_count`, `parse_line` |
| Structs, enums, traits, enum variants | `UpperCamelCase` | `UserAccount`, `Shape::Circle` |
| Constants and statics | `SCREAMING_SNAKE_CASE` | `MAX_USERS` |
| Type parameters, lifetimes ([Lifetimes](/learn/lifetimes/)) | one capital letter; short lowercase after `'` | `T`, `'a` |

Acronyms count as one word (`Uuid`), and the built-in types are lowercase (`i32`, `str`).

<ForLang only="go java kotlin csharp typescript">

Your `userCount` or `ParseLine` becomes `user_count` or `parse_line`. Type names such as `UserAccount` stay as they are.

</ForLang>

<ForLang only="go">

In Go a capital letter exports a name. In Rust case does not control visibility: the `pub` keyword does ([Modules](/learn/modules/#private-by-default)).

</ForLang>

## A `char` is not a byte

A Rust `char` is one Unicode scalar value and is 4 bytes wide, while a `u8` is one byte. A `"string"` is bytes in UTF-8, so its `len()` can be larger than its number of characters:

<Snippet file="char-size.rs" />

<ForLang only="java">

A Java `char` is a 16-bit unit of UTF-16, so a character outside the basic plane (such as the crab) takes two `char`s:

<Snippet file="char-size.java" />

</ForLang>

<ForLang only="kotlin csharp">

A `Char` in Kotlin and a `char` in C# are 16-bit UTF-16 units, so a character outside the basic plane (such as the crab) takes two of them. A Rust `char` holds the whole code point.

</ForLang>

<ForLang only="c cpp">

C and C++ `char` is a byte: it is Rust's `u8`. Rust's `char` is nearest to `char32_t`.

</ForLang>
