<p class="lr-layer" id="layer-toolkit">The toolkit</p>

Three things in Rust code look like noise until someone names them: a `!` after a name (`println!`), a line that starts with `#[` (`#[derive(Debug)]`), and a comment that starts with `///`. This page names each one and maps it from your language. It does not teach what the features are for (traits, tests, modules): it says "a later lesson" or links to the lesson that does.

## The `!`: a macro call

An ordinary Rust function has a fixed list of parameters: there is no `*args`, no `...rest`, no `printf`-style `...`. Yet `println!` takes any number of arguments, and checks its format string against them before the program runs. It can because it is a **macro**: code that the compiler expands into other code before it checks types ([the Book](https://doc.rust-lang.org/book/ch20-05-macros.html)). The `!` is the marker; in C nothing at the call tells you a macro is involved, apart from the habit of capital letters. You will use macros constantly and write them rarely.

| Macro | What it does |
|---|---|
| [`print!`](https://doc.rust-lang.org/std/macro.print.html) [`println!`](https://doc.rust-lang.org/std/macro.println.html) `eprintln!` | Print to standard output, with or without a newline; `eprintln!` to standard error. |
| [`format!`](https://doc.rust-lang.org/std/macro.format.html) | Build a `String` instead of printing. |
| [`vec!`](https://doc.rust-lang.org/std/macro.vec.html) | Build a `Vec`, a growable list ([Vectors](/learn/vectors/)). |
| [`assert!`](https://doc.rust-lang.org/std/macro.assert.html) [`assert_eq!`](https://doc.rust-lang.org/std/macro.assert_eq.html) | Panic (stop the program with a message) if a condition is false, or two values differ. |
| [`matches!`](https://doc.rust-lang.org/std/macro.matches.html) | `true` if a value fits a pattern ([Match](/learn/match/)). |
| [`panic!`](https://doc.rust-lang.org/std/macro.panic.html) [`todo!`](https://doc.rust-lang.org/std/macro.todo.html) | Panic now. `todo!` marks code you have not written yet, as the exercises below do. |
| [`dbg!`](https://doc.rust-lang.org/std/macro.dbg.html) | Print the source location, the expression and its value to standard error, and give the value back. |
| [`write!`](https://doc.rust-lang.org/std/macro.write.html) | Like `format!`, but into something you pass in, such as a file. |

## Format strings

`println!`, `format!`, `write!`, `panic!` and the message of `assert!` take a **format string**: text where `{...}` marks a place for a value. What follows a colon inside the braces says how to print it.

| You write | It means |
|---|---|
| `{}` | The next argument, in its `Display` form: the one meant for people. |
| `{:?}` and `{:#?}` | The `Debug` form: the one meant for programmers. `#` spreads it over several lines. |
| `{0}`, `{name}` | An argument by position or by name. `{name}` alone uses the variable `name` in scope. |
| `{:5}` `{:<5}` `{:^5}` `{:>5}` | A width of 5, then left, centre and right alignment. `{:*^9}` picks the fill character. |
| `{:05}` `{:+}` `{:.2}` `{:8.3}` | Zero padding. Always show the sign. Digits after the decimal point. Width, then precision. |
| `{:x}` `{:#x}` `{:b}` | Hexadecimal, hexadecimal with `0x`, binary. Flags combine: `{:#010b}` is the `0b` prefix, zero fill and width 10. |
| `{:w$}` `{:.p$}` | Width and precision taken from variables `w` and `p`. |
| `{{` and `}}` | One brace each. |

<Snippet file="format-specs.rs" />

Text is left-aligned by default and numbers right-aligned. A value wider than its width is not cut off. Width counts `char`s (Unicode scalar values), not bytes or screen columns, and on text `.3` is a maximum length. The [std::fmt docs](https://doc.rust-lang.org/std/fmt/index.html) list the whole grammar.

`Display` and `Debug` are **traits**: named abilities a type can have ([Traits](/learn/traits/)). Text has both; your own struct has neither until you add it:

<Snippet file="debug-missing.fail.rs" />

So a `log(format, args...)` wrapper cannot forward them to `println!`: take a finished `String` (callers write `log(&format!(...))`) or write a macro. Forwarding with `format_args!` and `fmt::Arguments` is covered in [Printing and Formatting](/learn/formatting/#format_args-and-what-format-costs).

## Attributes: `#[...]`

An **attribute** is a note to the compiler about the thing after it: a function, a struct, a field, a statement. With a `!`, as in `#![...]`, the note is about the thing it sits inside, such as the file or module.

| Attribute | What it does |
|---|---|
| `#[derive(Debug, Clone, PartialEq)]` | On a struct or enum: the compiler writes the standard code for those traits. `Debug` is what `{:?}` needs, `Clone` gives you `.clone()`, `PartialEq` is what `==` needs. |
| `#[test]` | Marks a test function. It is built and run by `cargo test`, and left out of a normal build. |
| `#[cfg(...)]` | Keep the item only when a condition holds, such as `target_os = "linux"` or `test`; `not(test)` is the opposite. |
| `#[allow(...)]` `#[warn(...)]` `#[deny(...)]` | Set what a lint does. See below. |
| `#[deprecated]` `#[must_use]` | Callers get a warning if they use the item, or ignore its result. |
| `#[tokio::main]` `#[serde(...)]` | Attributes that crates (libraries) define. See [Macros you'll read](/learn/reading-macros/#attribute-macros). |

<Snippet file="derive.rs" />

A derive works on the type directly below it, every field must have the trait too, and attributes stack. `Clone` is an explicit copy of the whole value. (`Partial` in `PartialEq` is explained in [Common traits](/learn/common-traits/#equality-order-and-hashing).)

<Snippet file="cfg.rs" />

That is the page's runner (Linux, a debug build). `cfg!(debug_assertions)` is true when the build has no optimisation ([Reference](https://doc.rust-lang.org/reference/conditional-compilation.html)), as in a plain `cargo build`.

### Lints

A **lint** is a check on style or on likely mistakes. Each has a level, usually `allow` (silent), `warn` (a message, the build continues) or `deny` (an error). An attribute changes the level for the thing below it, and `#![deny(...)]` for the whole file. The naming checks in [Declarations](/learn/declarations-types/#naming) are lints. The page shows compiler messages only for failures, so this program runs plain `rustc` on a three-line file three times (as it is, with `#[allow]`, with `#![deny]`) and prints the relevant lines. You would see them with `cargo build`.

The note under the warning says `on by default`: that lint warns without any attribute.

## Comments and documentation

| Form | What it is |
|---|---|
| `// text` | A comment to the end of the line. A plain `//` above a function is only a comment, not documentation. |
| `/* text */` | A block comment. Block comments nest. |
| `/// text` | Documents the item below it, in Markdown. (`/** text */` works too.) |
| `//! text` | Documents the file or module around it. It is usually the first lines of a file. |

<Snippet file="comments.rs" />

The [Reference](https://doc.rust-lang.org/reference/comments.html) says `/// Foo` is the same as `#[doc=" Foo"]`: a doc comment is an attribute in a friendlier form. `cargo doc --open` turns doc comments into web pages and opens them ([the Book](https://doc.rust-lang.org/book/ch14-02-publishing-to-crates-io.html#making-useful-documentation-comments)). In a library crate (`cargo new --lib`), a code block in a doc comment is also a test that `cargo test` runs. Cargo takes doc tests from the [library target only](https://doc.rust-lang.org/cargo/commands/cargo-test.html#documentation-tests), so examples in a binary crate's `main.rs` are not run.

## What you write today, in Rust

Each row is the closest match, not an exact one.

<ForLang only="go">

| You write in Go | In Rust |
|---|---|
| `fmt.Printf("%d %s\n", n, name)`, `Sprintf`, `Fprintf` | `println!("{} {}", n, name);` or `println!("{n} {name}");`, `format!(...)`, `write!(...)` |
| `%5d` `%-5d` `%05d` `%+d`; `%8.3f` `%x` `%#x` | `{:5}` `{:<5}` `{:05}` `{:+}`; `{:8.3}` `{:x}` `{:#x}` |

| `%v` `%+v` `%#v` on any struct; a `String() string` method | `{:?}` `{:#?}`, but only after `#[derive(Debug)]` (Go prints any struct with no setup); `impl Display` ([Common traits](/learn/common-traits/#printing-debug-and-display)) for `{}` |
| `` `json:"name"` `` (struct tag) | `#[serde(rename = "name")]`, from the [serde](https://serde.rs/field-attrs.html) crate |
| `//go:build linux` (a whole file) | `#[cfg(target_os = "linux")]` (one item) |
| `func TestAdd(t *testing.T)` in `x_test.go` | `#[test] fn adds()`, in the same file |
| `//nolint:name`, `gofmt`, `go vet`, staticcheck | `#[allow(name)]`, `cargo fmt`, `cargo clippy` |
| `// Add adds two numbers.` | `/// Adds two numbers.` in Markdown |

## Writing a macro: `macro_rules!`

`macro_rules!` lets you write your own macro. A parameter such as `$x:expr` stands for one whole parsed expression, and a variable the macro creates is separate from the caller's. The Reference calls this "mixed-site hygiene": loop labels, block labels and local variables are looked up where the macro was defined, other names where it is called. Hygiene does not stop a macro evaluating its argument once per use (twice here), as a function would not:

<Snippet file="macro-hygiene.rs" />

In `double_into!(tmp, 5)` the macro's `tmp` and the caller's `tmp` are different variables, so the caller's is set to 10. [Macros you'll read](/learn/reading-macros/) shows how to read a `macro_rules!` block.

<ForLang only="c">
