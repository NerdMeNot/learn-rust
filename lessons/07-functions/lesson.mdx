How the body ends (the tail expression: the last line, with no `;`) is in [Statements and expressions](/learn/statements-expressions/), and reading a signature piece by piece is in [Reading signatures](/learn/reading-signatures/). ## The signature is the contract

Each parameter is `name: Type` and the result follows `->` ([the spelling](/learn/declarations-types/#the-pieces-in-one-table)). No `->` means the function returns `()`, the value for "nothing" ([unit](/learn/statements-expressions/#-the-value-for-nothing)), and `-> !` means it never returns ([never type](/learn/statements-expressions/#when-nothing-comes-back-the-never-type)).

<Snippet file="signature.rs" />

Inside a body Rust works out types for you ([Variables](/learn/variables/)); in a signature the type is required for every parameter. Leave one out and the compiler complains at the comma. Grouping, as in `a, b: i32`, leaves `a` without one:

<Snippet file="grouped.fail.rs" />

Leave the return type out and it is `()`, so a body that produces a number is a mismatch. The compiler's `help` line suggests the type:

<Snippet file="no-return-type.fail.rs" />

## Arguments are passed by value

Every argument is handed to the parameter: copied for simple values such as numbers, moved for others. The parameter is a new variable: changing it needs `mut`, and does not change the caller's. A `let` with the same name hides it ([shadowing](/learn/declarations-types/#patterns-in-let-and-shadowing)):

<Snippet file="params.rs" />

A `String` is not copied for you. Passing it gives it away, and the caller cannot use it afterwards:

<Snippet file="moved.fail.rs" />

That is the ownership rule, taught in [Ownership](/learn/ownership/) (which values are copied is in [Copy or reference?](/learn/copy-or-reference/)). The usual fix is to pass `&name`, a borrow ([Borrowing](/learn/borrowing/)), so the caller keeps the value.

## Functions are values

A function's name converts to a **function pointer**, whose type is written `fn(i32) -> i32`. A closure that captures nothing converts to one too:

## Your habits, in Rust

<ForLang only="go">

| You write in Go | In Rust |
|---|---|
| `func add(a, b int) int` | `fn add(a: i32, b: i32) -> i32`: each parameter has its own type |
| `func f() (int, int)`, `q, r := f()` | returns a tuple: `let (q, r) = f();` ([Tuples](/learn/tuples/)) |
| `(int, error)`, `if err != nil` | `Result<i32, String>`; `?` passes the error up ([Errors](/learn/errors/)) |
| named results and a bare `return` | none: return a value |
| `q, _ := f()`, `func f(_ int)` | `let (q, _) = f();`, `fn f(_x: i32)` |
| `nums ...int`; `sum(1, 2)`, `sum(xs...)` | `nums: &[i32]` (a [slice](/learn/vectors/#slices-a-window-onto-a-list)); `sum(&[1, 2])`, `sum(&xs)` |
| `func (c *Counter) Inc()` | a method in an `impl` block ([Methods](/learn/methods/)) |
| `func f(p *int)` that writes `*p`; `f(&x)` | `fn f(p: &mut i32)`; `f(&mut x)` ([Mutable borrows](/learn/mutable-borrows/)) |
| `length(name)` copies the string, a struct is copied whole; the caller keeps its own | the value moves into the call, and the caller cannot use it afterwards |
| `func(int) int` as a parameter, `func(n int) int { ... }` | `impl Fn(i32) -> i32`; `fn(i32) -> i32` only when nothing is captured |

</ForLang>

|---|---|

## `impl Trait` as a parameter type

`impl Fn(i32) -> i32` or `impl Display` means "any type that can do this" ([how to read it](/learn/reading-signatures/#one-program-every-piece)). The Reference calls it an anonymous type parameter: the caller picks the type, the body may use only what the trait provides. A closure that captures works here, and so does a number or a string. See [Traits](/learn/traits/) and [Generics](/learn/generics/).

A `const fn` can be run by the compiler while compiling, when it is called in a `const`, a `static` or an array length ([Declarations and types](/learn/declarations-types/#constants-and-array-lengths)).
