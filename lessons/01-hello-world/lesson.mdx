<p class="lr-layer" id="layer-toolkit">The toolkit</p>

This page covers what sits between typing `cargo run` and seeing a line: the commands, the project folder, and `main`. Format strings are in [Macros, attributes, naming](/learn/macros-attributes-naming/#format-strings); arguments and environment variables are in [Arguments, Environment, Time and Processes](/learn/env-time-process/). Outputs come from Linux on 64-bit ARM with Rust and Cargo 1.99.1. Phrasebooks: [C and C++](/for/c-cpp/), [C#](/for/csharp/), [Go](/for/go/), [Java](/for/java/), [Kotlin](/for/kotlin/), [Python](/for/python/), [TypeScript](/for/typescript/). The programs that run `cargo` build a throwaway project in a temporary folder and trim the build times and that folder's name; read their output, not their code.

## The commands

| Command | What it does |
|---|---|
| `cargo new hello` | Makes a folder `hello/` with a project in it. |
| `cargo run` | Builds if anything changed, then runs the executable. |
| `cargo build` | Builds only. The executable goes in `target/debug/`. |
| `cargo check` | Looks for compile errors and makes no executable. |
| `cargo build --release`, `cargo run --release` | The optimised build, in `target/release/`. |
| `rustc main.rs` | The compiler by itself, for one file with no project. |
| `cargo add`, `cargo test`, `cargo fmt`, `cargo clippy` | Add a dependency; run tests; format; lint. |

<Snippet file="new-run.rs" />

`Cargo.toml` is the **manifest**: the package's name, version, `edition` (see [Editions](#editions)) and dependencies, none yet. `src/main.rs` is the root of the program and holds `fn main`. A **crate** is one unit of compilation. Two more paths matter:

| Path | What it is |
|---|---|
| `Cargo.lock` | Appears after the first build or check: the exact version of every dependency used ([the Book](https://doc.rust-lang.org/book/ch01-03-hello-cargo.html)). |
| `target/` | Everything the build makes. The `.gitignore` that `cargo new` wrote lists it. |

[Your first project](/start/first-project/) walks through the same commands with Cargo's progress lines.

## `fn main`

Execution starts at `fn main`, which has no parameters and by default returns `()`, [unit, the value for "nothing"](/learn/statements-expressions/#-the-value-for-nothing). Command-line arguments come from [`std::env::args()`](https://doc.rust-lang.org/std/env/fn.args.html), whose first item is the program itself, as in C, so `.nth(1)` (used by the programs below) is the first real argument ([Arguments, Environment, Time and Processes](/learn/env-time-process/) runs it). With Cargo, give the program its arguments after `--`, as in `cargo run -- a b` ([`cargo run`](https://doc.rust-lang.org/cargo/commands/cargo-run.html)).

## Standard output and standard error

A program has two output streams; a terminal shows both, and `cmd > out.txt` keeps only the first.

| Macro | Stream | Newline | Use it for |
|---|---|---|---|
| `print!`, `println!` | standard output | no, yes | The program's result. |
| `eprint!`, `eprintln!` | standard error | no, yes | Errors, warnings, progress. |
| `dbg!` | standard error | yes | Debugging. Prints `[file:line:column] expression = value` and returns the value. |

The program below prints on both streams, then runs itself again to catch each separately; a terminal would show them mixed.

`dbg!(21 * 2)` printed its source location and expression, and `doubled` still got `42`. It uses the `Debug` form, the programmer-facing way to print a value (`{:?}`, in [Macros](/learn/macros-attributes-naming/#format-strings)).

A panic (a crash with a message) is a third way to end:

<Snippet file="panic-exit.panic.rs" />

| `main` ends with | Exit code | Printed on standard error |
|---|---|---|
| `()` | 0 | |
| `Ok(())` | 0 | |
| `Err(e)` | 1 | `Error: ` and the `Debug` form of `e` |
| `ExitCode::SUCCESS` | 0 | |
| `ExitCode::from(n)`, with `n` a `u8` (0 to 255) | `n` | |
| a panic | 101 | the message |

The rule is the [`Termination`](https://doc.rust-lang.org/std/process/trait.Termination.html) trait (a named ability a type has: [Traits](/learn/traits/), later), which `()`, `ExitCode` and `Result<T, E>` (when `T` implements it too and `E` has a `Debug` form) implement. Anything else, such as an `i32`, is the compile error in the gotcha at the top of this page.

## Debug and release builds

Cargo has two **profiles**. `cargo build` and `cargo run` use `dev`, which does not optimise and keeps debugging information (Cargo prints `[unoptimized + debuginfo]`); `--release` uses `release`, which optimises. They write to different folders, so switching does not overwrite the other build. `cargo check` leaves out the executable, which this program shows:

<Snippet file="profiles.rs" />

`debug_assertions` is on in `dev` and off in `release`, and `debug_assert!` uses it. [Numbers and Types](/learn/types/) describes a setting that changes what a program does (integer overflow is a panic in `dev` and wraps in `release`); the [Cargo book](https://doc.rust-lang.org/cargo/reference/profiles.html) lists them all. Use `dev` while you write, and `release` for the build you measure or ship.

## `print!` and the buffer

Rust's standard output is **line-buffered**: text waits in memory until a newline arrives. The [`Stdout` docs](https://doc.rust-lang.org/std/io/struct.Stdout.html) say so for a terminal, and the run below shows a pipe doing the same on this platform. A full line leaves at once. ## Editions

`edition = "2024"` in `Cargo.toml` names a set of language rules. Editions let Rust change syntax without breaking old code: each package chooses its own, and `cargo new` writes the newest. `rustc main.rs` has no manifest to read, so it uses edition 2015 unless you pass `--edition`.
