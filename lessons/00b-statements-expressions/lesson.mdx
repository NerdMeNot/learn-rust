## Statement or expression?

An **expression** is code that produces a value: `7`, `x + 1`, `f(x)`. A **statement** is an instruction that does something and produces no value, such as `let x = 7;`. Many languages keep the two apart. In Rust, `if`, `match`, `loop` and `{ }` blocks are expressions too, so they can sit on the right of a `let` or be the last line of a function. The Reference: "Rust is primarily an expression language."

The last expression of a block, with no `;`, is the block's value. It is called the **tail expression**, a name you will see in compiler errors.

| Code | What it is | Its value | Learn more |
|---|---|---|---|
| `x + 1`, `f(x)` | expression | a number, a string, and so on | [Types](/learn/types/) |
| `{ let w = 3; w * 4 }` | block expression | its tail expression | below |
| `if c { a } else { b }` | expression | `a` or `b`, which must agree on a type | [If / else](/learn/if-else/) |
| `match n { 1 => "one", _ => "many" }` | expression | the chosen arm (`_` means "anything else") | [Match](/learn/match/) |
| `loop { ... break v; }` | expression | the `v` after `break` | [Loops](/learn/loops/) |
| `while c { }`, `for x in a..b { }` | expression | `()` (`a..b` runs from `a` up to, not including, `b`) | [Loops](/learn/loops/) |
| `x = 5`, `x += 1` | expression | `()` | [Variables](/learn/variables/) |
| `return v`, `break`, `continue`, `panic!("...")` | expression | none: they leave, so their type is `!` ("never", not the macro `!`) | [the never type](#when-nothing-comes-back-the-never-type) |
| `let x = 5;` | statement | none | [Variables](/learn/variables/) |
| `expr;` | statement | the value is dropped | next section |

Four of these side by side. Each `let` takes the value of a block, an `if`, a `match` and a `loop`. (`{block}` in a string prints the variable. `let mut` makes a variable that can change. The `!` in `println!` marks a macro: see [Rust at a glance](/learn/rust-at-a-glance/).)

## The semicolon decides

A `;` turns an expression into a statement and drops its value. A block whose last line has no `;` is worth that last line. A block that ends in a `;` is worth `()`. (`{a:?}` prints a value in its debug form.)

<Snippet file="semicolon.rs" />

That is the rule behind "no `return` at the end of a function": the body is a block, and its tail expression is the result. `return` is for leaving early. `return x;` as the last line is legal, but `clippy`, Rust's standard linter, warns about it by default ([`needless_return`](https://rust-lang.github.io/rust-clippy/rust-1.99.0/index.html#needless_return)).

The gotcha above is this rule in a function. Its code, E0308, means "mismatched types" ([all codes](/errors/)). It appears the other way round too: an `if` with no `else` must be worth `()`, so a value inside it needs a `;`. `main` returns `()`, so this `if` is its last expression:

<Snippet file="statement-if.fail.rs" />

## `()`, the value for "nothing"

`()` is called **unit**: a type with exactly one value, also written `()` (the empty tuple). A function with no `->` returns it, and so do `println!`, assignment, `while` and `for`. `size_of::<()>()` is the size in bytes of the type `()`. (`_` means "I don't need the value".)

<Snippet file="unit.rs" />

It is not a null: a variable of another type cannot hold it. It is a real value you can store, which a `void` result is not in C, C++, Java, C# or Go (an error in each). Python's `None`, Kotlin's `Unit` and TypeScript's `undefined` are the closest relatives.

## Assignment is worth `()`

In C, Java, C#, C++ and TypeScript, `a = b = 5` works because `b = 5` is worth 5. In Rust `b = 5` is worth `()`, so the chain is a type error:

## Why the language is built this way

The Reference: "statements serve mostly to contain and explicitly sequence expression evaluation". The Book: statements perform an action and return no value; expressions evaluate to one. Two things follow. With `if` giving a value, Rust has no need for `?:`. And a function's result needs no separate mechanism: the body is a block, and a block has a value. The cost is the gotcha's trap: in C or Java the final `;` is punctuation, and in Rust it changes the type.

## A `}` can end a statement

Where a statement is expected, a block-like expression (`if`, `match`, `loop`, `{ }`) ends at its closing brace. When that is ambiguous, the Reference says, "it is parsed as a statement". So a last line of `if ... { } else { } + 1` does not mean what it looks like. Read the first message; the `return` suggestions after it are side effects:

<Snippet file="statement-end.fail.rs" />

After `let t =` there is no ambiguity, so `let t = if n > 0 { 10 } else { 20 } + 1;` works (it gives 11). Elsewhere, wrap the `if` in parentheses, as the compiler suggests, or name it first.

## `if` without `else`, and loops that give a value

An `if` with no `else` has nothing to give when the condition is false, so its value is `()`. That is why it cannot be used for a value:

Of the three loops, only `loop` can hand back a value with `break value`. The Reference says a `while` expression evaluates to `()`, and the compiler allows `break` with a value only in a `loop` (or a labeled block, which this page does not cover):

## When nothing comes back: the never type

`return`, `break`, `continue` and `panic!` leave the current spot and never produce a value. Their type is `!`, read "never" (a different `!` from the macro mark). Because they cannot produce anything, the compiler accepts them where any type is expected, and that is what makes these lines work:

<Snippet file="never.rs" />

In `let even = if i % 2 == 0 { i } else { continue };` the first branch gives an `i32` and the `else` branch never gives anything, so the whole `if` is an `i32`.

<ForLang only="java">

Java has no such type: `ok ? 5 : throw new ...` is a syntax error. You write an `if` statement instead.

<Snippet file="throw-ternary.fail.java" />

</ForLang>

<ForLang only="kotlin">

This is Kotlin's `Nothing`: `if (ok) 5 else throw ...` has type `Int` for the same reason.

</ForLang>

<ForLang only="csharp cpp">

C# and C++ both let `throw` stand in a `?:` arm (`ok ? 5 : throw ...` compiles in each). That is the same idea.

</ForLang>

## Where this is awkward

- The `;` decides the type, and a last line without one is easy to miss when reading.
- A function body is always a block, so Kotlin's `= x + 1` and C#'s `=> x + 1` have no counterpart.
