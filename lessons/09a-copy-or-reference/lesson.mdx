<p class="lr-layer" id="layer-toolkit">The toolkit</p>

Every language has moments where you cannot tell whether a loop gave you the item or a copy of it, or whether a function changed your data. This page gives you tests that find the answer in your own language, then shows where Rust writes it down. Outputs come from the site's runner (Linux, ARM64; Go 1.27.3, Java 25, Python 3.13, Rust 1.99.1).

## One question, three answers

Ask one question: **if I change this, does anyone else see it?** There are three answers.

| Answer | What the new name holds | Who sees a change |
|---|---|---|
| A **copy** | its own bytes of data | nobody else |
| A **shared reference** | an arrow to the same data | everybody with an arrow |
| A **move** (Rust) | the data, handed over from the old name | nobody: the old name stops working |

In most languages `b = a`, `f(a)` and `for x in xs` copy the variable's bytes ([Values, the Stack and the Heap](/learn/stack-heap/)); C++ runs the type's copy constructor instead, and a `std::vector` copies its elements. What differs is what the bytes are, **the data or an arrow to it**. Rust splits "shared" in two: `&` is a read-only arrow, `&mut` one that may change the data (one at a time). The **type test** asks what the bytes are; **mutate and look** changes a copy and looks at the original.

| Where it hides | What to ask |
|---|---|
| `b = a`, `f(a)` | the data or an arrow? ([your language](#detectors-in-your-own-language)) |
| `for x in xs` | is `x` the element or a copy of it? ([Rust loops](#loops)) |
| a closure | the variable or a copy? ([Rust](#closures)) |
| a method call | the object or a copy? |
| a struct or list that holds things | most languages copy the top level only (a **shallow** copy); C++ containers and Rust `.clone()` copy what they own ([below](#shallow-and-deep)) |
| returning or storing a value | a value type is copied, an object stays shared |

## Detectors in your own language

When you are stumped, run this recipe on the thing you are unsure about:

1. Make `b` from `a` the way your code does (`b = a`, a call, a loop).
2. Change something *inside* `b`: an element or a field. Do not assign a whole new value to `b`: rebinding only moves `b`'s arrow, and is the usual cause of "references are passed by value" confusion.
3. Print `a`. If it changed, you shared. If it did not, you copied, or the object cannot change (an int, a string).
4. Ask the language for identity (below): do `a` and `b` lead to the same object or address?

## Rust writes the answer in the code

Rust has the same outcomes, but you can see which one you got, and the compiler stops the surprising ones. A plain name is a value; `&` or `&mut` in front is an arrow. `Copy` is a *trait*, a named ability: a `Copy` type is duplicated by `let b = a`, any other is moved.

| You write | You get | Afterwards |
|---|---|---|
| `let b = a;` for a `Copy` type | a copy | `a` still works and is separate |
| `let b = a;` for `String`, `Vec`, most structs | a move | `a` cannot be used |
| `let b = &a;` | a shared reference | `a` can be read, not changed, while `b` is in use |
| `let b = &mut a;` | a unique reference (one at a time; see [Mutable borrows](/learn/mutable-borrows/)) | `a` cannot be used while `b` is in use |
| `let b = a.clone();` | a new, separate value | `a` is unchanged |
| `f(a)`, `f(&a)`, `f(&mut a)` | the same three, for a parameter | |

The reference rows are the subject of [Borrowing](/learn/borrowing/). One of each:

### Loops

The way you write a `for` loop decides the type of `x`. This prints it for every form with `type_name_of_val` (`&x` only lets it look at `x`). Here `.iter()` walks by reference, `.iter_mut()` by `&mut` and `.copied()` yields a copy of each item ([Iterators](/learn/iterators/) comes later):

<Snippet file="loop-forms.rs" />

| You write | `x` is | Afterwards |
|---|---|---|
| `for x in &v`, `v.iter()` | `&i32`, a shared reference | `v` unchanged |
| `for x in &mut v`, `v.iter_mut()` | `&mut i32`, a reference you write through with `*x` | `v` changed |
| `for x in v.iter().copied()` | `i32`, a copy | `v` unchanged |
| `for x in v`, `v.into_iter()` | `i32`, taken out of `v` | `v` is gone |

The last row bites people who expect `for x in v` to behave like `range` or `for...in`:

<Snippet file="for-moves.fail.rs" />

The compiler names the loop and suggests `&ages`, the form that behaves like `range` or `for...of`.

When `x` is a `&mut`, `x.age += 1` and `x.len()` follow the reference for you. Only a bare change to the number itself needs `*x += 1`; forgetting it is the [gotcha](#gotcha) on this page. Inside a function that received `&mut Vec<T>`, the parameter is already the reference, so loop with `people.iter_mut()`.

### From your language to Rust

<ForLang only="go">
| Go | Rust |
|---|---|
| `for _, p := range people` (a copy of each) | `for p in &people` borrows each element. `for p in people.iter().cloned()` is the visible copy (needs `#[derive(Clone)]`) |
| `for i := range people { people[i].Age++ }`, or `p.Age++` over a `[]*Person` | `for p in &mut people { p.age += 1; }` |
| `b := a` (a struct) | `let b = a;` copies if the struct is `Copy`, else moves. `a.clone()` is the explicit copy |
| `s := a[1:3]` | `let s = &a[1..3];` also shares, and you cannot `push` to the `Vec` `a` while `s` is in use |
| `m[k].Age++` (error) | `if let Some(p) = m.get_mut(k) { p.age += 1; }` |
| `func (c Counter) Value()` | `fn value(&self)`. A plain `self` takes the value: a move unless the type is `Copy`, which Go has no form for |
| `func (c *Counter) Inc()` | `fn inc(&mut self)` ([Methods](/learn/methods/)) |
</ForLang>

<ForLang only="java kotlin csharp">
| You write | Rust |
|---|---|
| `for (Person p : people) p.age++` | `for p in &mut people { p.age += 1; }` |
| `Person b = a;` (two names that can both change one object) | `let b = &a;` is a read-only second name. Rust gives no plain form for two names that both change; `&mut a` makes `a` unusable while `b` lives |
| `void f(Person p)` | `fn f(p: &mut Person)` changes yours, `&Person` reads, `Person` takes it |
| `a.equals(b)`, `a == b` on objects | `a == b` compares contents (for types that derive `PartialEq`), `std::ptr::eq(&a, &b)` is identity |
| `clone()`, Kotlin `copy()`, C# `with` | `.clone()`. Those are shallow (Java's array `clone()` shared its elements above); Rust's copies everything the value owns |
| Java lambda: copy of the value, variable must not change | Rust closure: borrows the variable and may change it; `move` takes it |
</ForLang>

<ForLang only="python typescript">
| You write | Rust |
|---|---|
| `for p in people: p.age += 1` | `for p in &mut people { p.age += 1; }` |
| `b = a` (two names that can both change one object) | `let b = &a;` is a read-only second name. Rust gives no plain form for two names that both change: one `&mut` at a time, or `Rc` with `RefCell` ([Smart pointers](/learn/smart-pointers/#rcrefcellt-shared-and-changeable)) |

| `a[1:3]`, `a.slice(1, 3)` (a new list) | `&a[1..3]` is a view of the same items; `a[1..3].to_vec()` is the copy |
| `def f(items): items.append(1)` | `fn f(items: &mut Vec<i32>)` |
| `a is b`, `a === b` | `std::ptr::eq(a, b)` on two references |
</ForLang>

<ForLang only="c cpp">
| You write | Rust |
|---|---|
| `for (auto x : v)` | `for x in v.iter().copied()` (`.cloned()` for a `String`) |
| `for (auto& x : v)` | `for x in &mut v` |
| `for (const auto& x : v)` | `for x in &v` |
| `T copy = a;` (C++) | `let copy = a.clone();`, since a heap type never copies silently |
| `std::move(a)` | `let b = a;`. A move is already the default, and unlike C++ the moved-from `a` cannot be used |
| `T*` or `T&` that you change; `const T&` | `&mut T`; `&T`. Both are checked |
| `std::shared_ptr` | `Rc` (`Arc` across threads), [Smart pointers](/learn/smart-pointers/#rct-several-owners) |
| `[=]` and `[&]` in a lambda | roughly `move \|\| ...` and `\|\| ...`. `move` copies a `Copy` value but takes anything else; `.clone()` first for a C++-style copy |
</ForLang>

### Which types are `Copy`

Numbers, `bool`, `char`, shared references `&T`, and tuples, arrays and `Option`s of `Copy` things. `String`, `Vec` and `Box` own heap memory, so they are not, and neither is `&mut T`. Your own struct is not `Copy` until you write `#[derive(Clone, Copy)]`, which needs every field to be `Copy`. The [`Copy` docs](https://doc.rust-lang.org/std/marker/trait.Copy.html) list the standard ones, and the compiler tells you the rest (ignore the syntax here; the error is the point):
