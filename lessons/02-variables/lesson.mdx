## Frozen unless you say `mut`

A `let` variable cannot be assigned to once it has a value (E0384, in the gotcha above); `mut` lifts that. It also freezes the value the variable owns.

<Snippet file="frozen-vec.fail.rs" />

E0596. `push` changes the list, and its variable is not `mut`. The message says "borrow as mutable": a method that changes a value borrows it mutably ([Borrowing](/learn/borrowing/); `Vec` is a growable list, [Vectors](/learn/vectors/)). References and `Cell`-style types are the exceptions (Going deeper).

**Why is this the default?** The Rust Book's reason: if one part of the code assumes a value never changes and another changes it, the first part may misbehave. With plain `let` a reader need not check; only `let mut` variables need watching.

## Shadowing or `mut`?

Writing `let` again with the same name makes a **new** variable and hides the old one ([spelling](/learn/declarations-types/#patterns-in-let-and-shadowing)). The two tools do different jobs:

| | `let mut x` then `x = ...` | `let x = ...` again |
|---|---|---|
| Variable | the same one | a new one |
| Type | must stay the same | may change |
| Inside a block | the change outlives the block | the new variable ends with the block |
| Afterwards | still `mut` | frozen again, unless you write `let mut` |

<Snippet file="shadow-vs-mut.rs" />

`a` was changed for good. `b` was hidden inside the block and came back after it. A new variable can have a new type (these two sizes are two variables):

<Snippet file="shadow-type.rs" />

Assigning a different type to a `mut` variable is an error:

<Snippet file="mut-type.fail.rs" />

Use `mut` for something that really changes, such as a counter, and shadowing for a step that makes a new version of the same thing (`let input = input.trim();`, a conversion).

## `const`, `static` and `let`

| | `let` | `const` | `static` |
|---|---|---|---|
| Value | any expression, computed when the line runs | a constant expression, computed before the program runs | a constant expression |
| Can change | only with `mut` | never | not by assignment (atomic types and `Mutex` can change), and `static mut` needs `unsafe` for every use |
| In memory | a variable | copied into each place that uses it | one place; all references point to it |

The spelling, where each may sit are on [Declarations and types](/learn/declarations-types/#declaring-let-const-static), and the naming is under [Naming](/learn/declarations-types/#naming). The "In memory" row is the Rust Reference on [constants](https://doc.rust-lang.org/reference/items/constant-items.html) and [statics](https://doc.rust-lang.org/reference/items/static-items.html). ## Variables you do not use

An unused variable and a `mut` that is never needed are **warnings**, not errors: the lints [`unused_variables`](https://doc.rust-lang.org/rustc/lints/listing/warn-by-default.html#unused-variables) and [`unused_mut`](https://doc.rust-lang.org/rustc/lints/listing/warn-by-default.html#unused-mut) are on by default. `#![deny(unused)]` ([lint levels](/learn/macros-attributes-naming/#lints)) turns them into errors for the whole file:
