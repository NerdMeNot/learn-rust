<p class="lr-layer">The toolkit</p>

This page lists habits that fail in Rust, with the real compiler message and what to write instead. A message with no error code means the parser did not know the syntax; a code such as E0308 means the syntax was fine and the types were not. Outputs come from Linux on 64-bit ARM with Rust 1.99.1.

Two warnings. When the parser gets lost it names the token where it gave up, and the cause is that token or the one before. And a `help:` line is a guess: `count += 1` is the fix, but `goto done` gets "write `goto.done`" and `while item = items.next()` gets "compare with `==`". Read a guess before you apply it.

Three words recur: `Option` is a value that may be missing ([Option](/learn/option/)), `Result` is a success or an error ([Errors](/learn/errors/)), and `match` is Rust's `switch` ([Match](/learn/match/)).

### `--x` is not a decrement

`++x` is a syntax error, like `x++`. `--x` is valid, and its meaning depends on the language. In Rust it is `-(-x)`, as in Python, so `count` is unchanged. ## No fall-through, and `break` in a `match`

A `match` arm runs on its own, so there is nothing to fall through to; several values share an arm with `|`. A `break` in an arm leaves the enclosing loop, as `2 => break` does here:

## No mutable globals

A `static` is a global with one fixed place in memory. A plain one cannot be assigned. `static mut` can, but every read or write needs an [`unsafe` block](/learn/unsafe/#what-unsafe-unlocks) (a block where you promise the compiler you checked what it cannot):

<Snippet file="global-mut.fail.rs" />

Inside `unsafe` it compiles, but edition 2024 denies even printing the value:

<Snippet file="static-mut-print.fail.rs" />

For a counter that several threads may change, use an atomic: a number whose changes happen as one step. For larger values use a `Mutex` ([Shared state](/learn/shared-state/)). Every atomic method takes an `Ordering`, which says how much other memory the operation makes visible to other threads. `Ordering::Relaxed` keeps the counter itself exact and orders nothing else, which is all a plain counter needs; the [`Ordering`](https://doc.rust-lang.org/std/sync/atomic/enum.Ordering.html) docs explain the stronger ones.

## Where this costs you

- Numeric code that mixes widths, such as sizes (`usize`) and counters (`i32`), has more `as` and `from` calls.
- Without inheritance, shared behaviour comes from a trait, or a type holds the other as a field.
