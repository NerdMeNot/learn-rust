Rust's standard library, `std`, is smaller than Go's or Python's, on purpose. It has the building blocks every program needs: collections, files, text, threads, processes, time. Everything else comes from crates. This page shows what's in the box, what isn't, and how to read the docs without getting lost.

<Remember>As a rule of thumb: if it touches the operating system or nearly every program needs it, it's in `std`. If it might need to change, it's a crate.</Remember>

### Why is it so small?

Other languages made different bets. Anything stabilised in Rust's `std` has to keep working: the project's [2014 post on how Rust ships](https://blog.rust-lang.org/2014/10/30/Stability/) describes stable APIs as "a commitment to avoid breaking code that uses those features or APIs". That is fine for `Vec`, and costly for things that are still changing.

The `rand` crate has had four incompatible series in a row (0.7, 0.8, 0.9 and 0.10; in `0.x` versions Cargo treats each minor number as a breaking change). Async runtimes compete on different trade-offs. HTTP went from 1.1 to 2 to 3. Kept in crates, each can ship a better version without breaking anyone, and you choose when to upgrade.

The cost is that you pick crates yourself. [The crates everyone uses](/build/crates-map/) lists the usual choice for each job, with the caveat that "usual" is a judgement. `regex` is a good example of the line: it is maintained by [the Rust project's regex team](https://github.com/rust-lang/regex) (a subteam of libs, per [rust-lang/team](https://github.com/rust-lang/team/blob/main/teams/regex.toml)), but it is a separate crate, not part of `std`.

## What you get without importing anything

Every Rust file starts with a short list of names already imported, called the **prelude**. That's why `Vec`, `String`, `Option`, `Some`, `None`, `Result`, `Ok`, `Err` and `Box` just work, along with traits like `Clone`, `Iterator` and `ToString`. Everything else needs a `use` line, including `HashMap`. The [prelude docs](https://doc.rust-lang.org/std/prelude/index.html) say it is "kept as small as possible".

That catches people out: `Vec` is right there, but its sibling `HashMap` isn't. See the gotcha at the bottom.

## Reading a function signature

The docs at [doc.rust-lang.org/std](https://doc.rust-lang.org/std/) are the reference, and the signatures look dense at first. Once you can read them, a signature tells you a lot, including things that other languages' docs say only in prose. If the `rust-docs` component is installed (the default rustup profile includes it), `rustup doc --std` opens an offline copy.

Here are three real signatures from `std` (as the 1.99.1 docs show them), and what each piece means:

<Files guide="std-tour" dir="std-docs" files={["from the std docs"]} />

| When you see | It means |
| --- | --- |
| `&self` | Only reads the value. You can call it any number of times, and others can read at the same time. |
| `&mut self` | Changes the value. Nobody else can look while it runs. |
| `self` | Takes the value. You can't use it afterwards (unless it's `Copy`). |
| `-> Option<T>` | Might give back nothing. You must handle `None`. |
| `-> Result<T, E>` or `io::Result<T>` | Might fail. Use `?`, `match` or `unwrap_or`. |
| `-> &str` from `&self` | A view into the input, not a copy. It can't outlive the input. |
| `-> String`, `-> Vec<T>` | New memory you own. |
| `<P: AsRef<Path>>` or `impl AsRef<Path>` | Accepts any type that can be looked at as a path: `&str`, `String`, `PathBuf`. |
| `where K: Borrow<Q>` | A map with `String` keys can be searched with a plain `&str`. No temporary String needed. |
| `Q: ... + ?Sized` | Also works for types like `str` whose size isn't known. Safe to ignore while reading. |

The closest thing in your language, for the first seven rows:

<ForLang only="go">

`&self` is a method that only reads; `&mut self` is a pointer-receiver method that writes; `self` has no equivalent: Go copies a value receiver, and the caller keeps its own copy. `Option` and `Result` are `v, ok :=` and `v, err :=`. A `&str` view is a substring sharing memory, and `String` is a fresh allocation.

</ForLang>

<ForLang only="python typescript">

There is no marker for a method that only reads, or one that takes the value away: a method of a mutable object can change it. `Option` is `None` or `undefined` (a type checker can make you handle it; the runtime does not), and `Result` is an exception.

</ForLang>

<ForLang only="java kotlin csharp">

None of the three marks a method as "only reads" the way `&self` does (C# has `readonly` members, on structs only), and none has a `self` that takes the value away. `Option` is `Optional<T>` (Java) or a nullable `T?` (Kotlin, C#), and `Result` is an exception (Kotlin also has a `Result` type).

</ForLang>

<ForLang only="c cpp">

`&self` and `&mut self` are a `const` and a non-`const` method in C++, or `const T *` and `T *` in C. `self` is passing by value or `std::move`. `Option` is `std::optional` and `Result` is a return code, or `std::expected` in C++23. A `&str` view is `std::string_view`, or a pointer into the input.

</ForLang>

## Traits do half the work

On a type's docs page, scroll past its own methods to **Trait Implementations**. That's where many of the useful methods are hiding. `File` has very few methods of its own. Reading and writing come from `impl Read for File` and `impl Write for File`.

The catch: a trait's methods only work after you import the trait. The [Files and I/O](/learn/files-io/) gotcha is exactly this. These are the traits you'll meet constantly:

| Trait | What it gives you | Need a `use`? |
| --- | --- | --- |
| `Display`, `Debug` | `{}` and `{:?}` printing, and `.to_string()` | only to implement them (`use std::fmt`) |
| `Iterator` | `map`, `filter`, `sum`, `collect` and dozens more | no, it's in the prelude |
| `Read`, `Write`, `BufRead` | `read_to_string`, `write_all`, `writeln!`, `lines()` | yes: `use std::io::{Read, Write, BufRead}` |
| `FromStr` | `"42".parse::<u32>()` | no for `parse`; yes for `i32::from_str("42")` (`use std::str::FromStr`) |
| `From`, `Into` | conversions, and how `?` converts one error type into another | no |
| `Default` | `Type::default()`, an "empty" value | no |
| `Clone`, `Copy` | `.clone()`, and copy-instead-of-move for small types | no |
| `PartialEq`, `Eq`, `Ord` | `==`, sorting | no, usually derived |
| `Hash` | using a type as a `HashMap` key | `#[derive(Hash)]` needs no import; writing `T: Hash` as a bound does (`use std::hash::Hash`) |

:::tip[We've got you]
You don't have to memorise any of this. When a method is missing because its trait isn't imported, the compiler error names the exact `use` line to add, and rust-analyzer can add it for you. The tables are here so the error makes sense when you see it.
:::

## Three layers: core, alloc, std

`std` is actually built from two smaller libraries. `core` is everything that needs no memory allocation and no operating system: `Option`, `Result`, iterators, numbers. `alloc` adds heap types: `Box`, `Vec`, `String`. `std` adds the operating system: files, threads, networking, `Instant` and `SystemTime`. `HashMap` is in `std` too.

You'll only notice this when you write for a microcontroller or a kernel, where you say `#![no_std]` and keep just `core` (and maybe `alloc`). The same `Option` and iterators work there.
