You know Go. This page lists what you can keep, ten habits that will meet a compiler error, and where each is taught. Both languages ran in one image (Go 1.27.3, Rust 1.99.1, Linux ARM64), and all output and compiler messages are what the runs printed.

<Remember>Go trusts you with sharing and changing, and leaves the rest to `go vet`, the race detector and tests. Rust asks who owns a value, who may read it and who may change it, and refuses the program when the answer is unclear.</Remember>

## What carries over

- **Errors are values.** A failing call returns its error and you decide. `Result<T, E>` holds either the value or the error, where Go returns both ([Errors and Result](/learn/errors/)).
- **Structs and methods, no classes.** Data in a struct, methods in an `impl` block ([Structs](/learn/structs/), [Methods](/learn/methods/)).
- **A slice is a pointer, a length and a capacity.** A `Vec` has the same three words ([Ownership](/learn/ownership/)), and `&v[1..3]` is a window like `v[1:3]`.
- **Interfaces name what a function needs.** A trait does that job, and also works as a generic bound ([Traits](/learn/traits/)).
- **One tool does the chores.** `cargo` builds, runs, tests and formats like `go` (toolchain table below).

## Ten habits to unlearn

Each habit shows a Go program, the Rust that replaces it, and the compiler's message where Rust refuses.

### 1. `range` hands you a copy

In Go, `p` in `for _, p := range people` is a copy, so `p.Age++` changes the copy (the first line below shows the ages unchanged); you fix it by indexing. In Rust the loop says what you get: `&people` lends each element read-only, `&mut people` lends it for changing, and plain `people` moves the elements out.

### 3. `if err != nil` becomes a type, and `_` gets louder

`n, _ := strconv.Atoi("abc")` throws the error away: `n` is 0 and the program printed 1. In Rust, `parse` returns a `Result<i32, ParseIntError>`, which does not compile where an `i32` is wanted. `?` is close to a one-character `if err != nil { return err }`, and it converts the error type if needed.

### 5. Slices share an array; a `Vec` owns its items

In Go, `b := a[:2]` is a window onto `a`'s array, and `append(b, 99)` found room there and overwrote `a[2]`. In Rust a slice borrows from the `Vec`, which cannot grow while the borrow is alive. For an independent list you write `to_vec()`.

### 8. `defer` runs at the end of the function; `Drop` runs at the end of the scope

### 9. Goroutines can share whatever they can reach

In Rust, two closures that both change `count` do not build; the fix is to put the data inside a lock, which is a type.

### 10. Go has one `string`; Rust has two, and neither is indexed by byte

A Go `string` is bytes: `len(s)` counts them, `s[1]` is one of them, and `s[:2]` cut the `é` in half without a word (`"h\xc3"` is not valid UTF-8). Rust has `String` (owns the text) and `&str` (borrows it). `s[1]` does not compile. `&s[..2]` does compile, and panics at run time when 2 falls inside a character; `get` is the form that returns an `Option`, so that cut is `None`.

## Idiom by idiom

The two programs behind this table print the same 20 lines, which the last run below checks with `diff`.

| You write in Go | In Rust | Read |
| --- | --- | --- |
| `x := 5` then `x = x + 1` | `let mut x = 5;` then `x += 1;` | [Variables](/learn/variables/) |
| `var zero int` | `let zero = i32::default();` | [Common traits](/learn/common-traits/) |
| `for i := 0; i < 3; i++ { sum += i }` | `for i in 0..3 { sum += i; }` | [Loops](/learn/loops/) |
| `for i, w := range words { total += i * len(w) }` | `for (i, w) in words.iter().enumerate() { total += i * w.len(); }` | [Looping over collections](/learn/for-collections/) |
| `switch day { case "sat", "sun": kind = "weekend" }` | `let kind = match day { "sat" \| "sun" => "weekend", _ => "weekday" };` | [Match](/learn/match/) |
| `if v, ok := ages["ana"]; ok { ... }` | `if let Some(v) = ages.get("ana") { ... }` | [Maps](/learn/maps/) |
| `counts["the"]++` | `*counts.entry("the").or_insert(0) += 1;` | [Maps](/learn/maps/) |
| `v = append(v, 2)` | `v.push(2);` | [Vectors](/learn/vectors/) |
| `len(s)` (bytes) | `s.len()` (bytes) | [Strings](/learn/strings/) |
| `len([]rune(s))` | `s.chars().count()` | [Strings](/learn/strings/) |
| `len(strings.Fields("a b"))` | `"a b".split_whitespace().count()` | [Text](/learn/text/) |
| `n, err := strconv.Atoi("42")` | `"42".parse::<i32>()`, a `Result` | [Errors and Result](/learn/errors/) |
| `fmt.Sprintf("%s-%d", a, b)` | `format!("{a}-{b}")` | [Formatting](/learn/formatting/) |
| `sort.Ints(v)` | `v.sort();` | [Vectors](/learn/vectors/) |
| `strings.ToUpper("ana")` (ASCII here) | `"ana".to_uppercase()` | [Text](/learn/text/) |
| `a, b = b, a` | `(a, b) = (b, a);` | [Tuples](/learn/tuples/) |
| `min(p, q)` | `p.min(q)` | [Common traits](/learn/common-traits/) |
| `type Celsius float64` | `struct Celsius(f64);`, read as `c.0`; no arithmetic until you add it | [Structs](/learn/structs/) |
| `errors.New("bad input")` | `let e: Box<dyn Error> = "bad input".into();` | [Errors and Result](/learn/errors/) |
| `func (c *Counter) Inc() { c.n++ }` | `fn inc(&mut self) { self.n += 1; }` | [Methods](/learn/methods/) |

## The toolchain, side by side

| Job | Go | Rust |
| --- | --- | --- |
| New project | `go mod init example.com/demo` | `cargo new demo` |
| Add a dependency | `go get` (not run) | `cargo add` (needs the network; not run, see [Finding and using crates](/start/using-crates/)) |
| Build | `go build ./...` | `cargo build` |
| Run | `go run .` | `cargo run` |
| Test | `go test ./...` | `cargo test`, which also runs the examples in doc comments |
| Format | `gofmt -l .` | `cargo fmt --check` |
| Lint | `go vet ./...` | `cargo clippy` |
| Docs | `go doc strings.Fields` | `cargo doc --no-deps`, which writes HTML |
| Debugger | [Delve](https://github.com/go-delve/delve), `dlv` (not in the image) | `rust-gdb` or `rust-lldb` from the Rust install, or gdb or lldb directly (not run) |
| Other platforms | `GOOS=windows go build` | `cargo build --target ...` (see below) |

## What you will miss

Each point is backed by a run, a source or a lesson:

- **Cross-compiling with two variables.** Go built a Windows executable here with `GOOS=windows`. The image's Rust had one target, and asking for Windows failed. The [rustup book](https://rust-lang.github.io/rustup/cross-compilation.html) says `rustup target add` installs the standard library for a target and that you usually need a linker too. These steps need the network and were not run.
- **JSON in the standard library.** Go marshals a struct with `encoding/json` (below). Rust's `std` has no JSON; the usual answer is `serde` ([Serde](/build/serde/), [A map of crates](/build/crates-map/)).
- **Pointers that go anywhere.** Go keeps what is reachable alive. Rust's answers for graphs and parent links (indices, `Rc`, `Weak`) are in [Working with the borrow checker](/learn/borrow-checker/) and [Smart pointers](/learn/smart-pointers/).
- **`select`.** Channels in `std` have none ([Channels](/learn/channels/)).
- **Joining two third-party pieces.** In Go a type can satisfy an interface neither of you wrote. Rust's orphan rule (habit 4) refuses that impl; a newtype is the way round ([Traits](/learn/traits/#traits-for-types-you-did-not-write)).

## Try it yourself

Each task edits a program above; the sessions below ran in the image.

1. In habit 2, replace the `match` with `find(2).unwrap()`. It builds, then panics with ``called `Option::unwrap()` on a `None` value``: Go's nil crash again, but you wrote the word that allows it.
2. In habit 8, change `let _g = Guard(i);` to `let _ = Guard(i);`. Each `dropped` line now comes before its `loop` line: `_` does not bind the value, so nothing keeps it alive ([Patterns](/learn/patterns/)).
3. In the failing program of habit 9, put `move` on the closures and keep the plain `count`. It builds with two warnings and prints 0: each closure got its own copy of an `i32`. Safe Rust refuses data races; it does not refuse a program that gives the wrong answer.
