## 4. Which error code?

<Files guide="checkpoint-concurrency" dir="fails" files={["q4.rs"]} />

Does it compile? If not, which error code, and which trait does `RefCell<i32>` lack?

<details>
<summary>Answer</summary>

<Session guide="checkpoint-concurrency" run="q4" />

E0277, and `RefCell<i32>` lacks `Sync`. The compiler also says that `Arc<RefCell<i32>>` is not `Send`, and the two notes are one fact: an `Arc<T>` can move to another thread only when `T` is `Send` and `Sync`. Every thread holding the `Arc` gets a `&T`, and a `RefCell` changes its borrow count through `&self` with nothing to coordinate the threads. A `Mutex` is the thread-safe version. Taught in [`Arc<RefCell<T>>` fails, `Arc<Mutex<T>>` works](/learn/send-sync/#arcrefcellt-fails-arcmutext-works).

</details>

## 5. Which error code?

<Files guide="checkpoint-concurrency" dir="fails" files={["q5.rs"]} />

The thread is joined on the next line. Does it compile? If not, which error code?

<details>
<summary>Answer</summary>

<Session guide="checkpoint-concurrency" run="q5" />

E0373. A thread may outlive the function that started it, and the compiler does not use the `join` on the next line to decide otherwise, so the closure may not borrow a local. The suggestion is `move`. `thread::scope` is the tool that does let a thread borrow. Taught in [`move`: the thread owns what it uses](/learn/threads/#move-the-thread-owns-what-it-uses).

</details>
