### Question 2: the order things are dropped

<Files guide="checkpoint-abstractions" dir="rust" files={["src/bin/q2.rs"]} />

Does it compile? What are the seven lines, in order?

<details>
<summary>Answer</summary>

<Session guide="checkpoint-abstractions" run="q2" />

`let _ = ...` does not keep the value, so `ignored` is dropped on the spot. At the end of `main`, locals are dropped in the reverse of the order they were made: `y`, then `pair`, then `x`. The fields of `pair` are dropped in the order they are written, `first` and then `second`. See [Scopes, drop order and `let _`](/learn/ownership/#scopes-drop-order-and-let-_) and [`Drop`](/learn/common-traits/#drop-the-trait-behind-scope-exit).

</details>

### Question 3: a derived order

<Files guide="checkpoint-abstractions" dir="rust" files={["src/bin/q3.rs"]} />

Does it compile? What are the two lines?

<details>
<summary>Answer</summary>

<Session guide="checkpoint-abstractions" run="q3" />

A derived order compares enum variants by declaration order, and compares the data inside a variant only when both values are the same variant. So every `Mid(_)` sorts before `High`, whatever the number, and `Mid(2)` is before `Mid(5)`. See [Equality, order and hashing](/learn/common-traits/#equality-order-and-hashing).

</details>

### Question 4: a reading that is not there

<Files guide="checkpoint-abstractions" dir="rust" files={["src/bin/q4.rs"]} />

Does it compile? What are the four lines?

<details>
<summary>Answer</summary>

<Session guide="checkpoint-abstractions" run="q4" />

`NaN` is not equal to itself, so the derived `==` is `false` for `missing == missing`. `partial_cmp` returns an `Option<Ordering>` and gives `None` when two values cannot be put in order, and `<` on a `None` is `false`. Two ordinary readings are equal, as you would expect. See [Equality, order and hashing](/learn/common-traits/#equality-order-and-hashing).

</details>

## Predict the error

### Question 5: a reference outlives its text

<Files guide="checkpoint-abstractions" dir="rust" files={["src/bin/q5.rs"]} />

Does it compile? If not, which error code, and which line does the compiler say `line` is dropped on, and which line uses the borrow afterwards?

<details>
<summary>Answer</summary>

<Session guide="checkpoint-abstractions" run="q5" />

`Parser<'a>` holds a reference, so a `Parser` cannot live longer than the `String` it borrows. `line` is dropped at the closing brace of the inner block (line 10, marked "dropped here while still borrowed"), while `parser` is used after it (line 11, "borrow later used here"). See [Structs that hold references](/learn/lifetimes/#structs-that-hold-references) and [How long a borrow lasts](/learn/borrowing/#how-long-a-borrow-lasts).

</details>

### Question 6: a trait you cannot put in a box

<Files guide="checkpoint-abstractions" dir="rust" files={["src/bin/q6.rs"]} />

Does it compile? If not, which error code, and which method is to blame?

<details>
<summary>Answer</summary>

<Session guide="checkpoint-abstractions" run="q6" />

A `dyn Shape` forgets the concrete type, but `scaled` returns `Self`, and there is no way to say what `Self` is once the type is forgotten. The compiler's word for this is that the trait is not dyn compatible, and it names the method. See [Which traits can be `dyn`](/learn/trait-objects/#which-traits-can-be-dyn).

</details>

### Question 7: building through a private door

<Files guide="checkpoint-abstractions" dir="rust" files={["src/bin/q7.rs"]} />

Does it compile? If not, which error code, and which line?

<details>
<summary>Answer</summary>

<Session guide="checkpoint-abstractions" run="q7" />

The struct is `pub`, but its field is private, so code outside `bank` cannot name the field, and a struct literal has to name every field. `Account::new()` is the way in that the module chose to offer.
