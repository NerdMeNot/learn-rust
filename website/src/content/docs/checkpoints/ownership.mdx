Eight short programs, one question each, from the Ownership lessons (Stack and heap through Mutable borrows) and the parts before them. Decide first: does it compile, and what does it print? If it does not compile, which error code?

<Remember>Ask the same three questions of every line: who owns this value, who is borrowing it, and for how long?</Remember>

Each program is a file in a Cargo project (`src/bin/q1.rs` and so on) and runs with `cargo run --bin q1`. The answers are real runs in the page's image (Rust 1.99.1, edition 2024).

`let _ = Noisy("b")` binds nothing, so the value is dropped on that line. `take(a2)` moves `a2` into the function, which drops it when it returns, before `end`. Shadowing hides the first `_a` but does not drop it. At the closing brace the remaining variables drop in reverse order: the shadowing `_a`, `_c`, then the first `_a`. See [Scopes, drop order and `let _`](/learn/ownership/#scopes-drop-order-and-let-_).

`for x in &v` holds a read-only borrow of `v` for the whole loop, and `push` needs a mutable one. ## How to score yourself

Count a question as right when you gave the correct output, or the correct error code and the reason. The error questions use five codes that name five different problems: E0382 (use after a move), E0499 (two writers), E0502 (a writer while a reader is alive), E0505 (a move while a borrow is alive) and E0596 (writing through a `&`). If you mixed two of them up, compare their messages side by side: each one names what is borrowed or moved, and the line where the other use happens.

Question 2 and question 8 are about what the compiler does when nothing is wrong: the drop order and the partial move are rules, not mistakes, and they run the same way each time. Question 3 shows the difference between a value that is copied and a value that is lent.
