### Question 3: whose variable?

<Files guide="checkpoint-collections" dir="rust" files={["src/bin/q3.rs"]} />

Does it compile? What are the three lines of output?

<details>
<summary>Answer</summary>

<Session guide="checkpoint-collections" run="q3" />

The first closure borrows `count` and changes the real variable, so it ends at `2`. `move` gives the second closure its own copy of `n`, because a number is copied, and the two calls change that copy to 11 and then 12. The outer `n` is still `10`. See [What a closure captures](/learn/closures/#what-a-closure-captures) and [`move`: take ownership](/learn/closures/#move-take-ownership).

</details>

### Question 4: numbering backwards

<Files guide="checkpoint-collections" dir="rust" files={["src/bin/q4.rs"]} />

Both loops compile: a slice iterator can run from the back, which `rev` needs, and `enumerate` keeps that ability when it wraps one. What are the six lines? Do both loops print the same pairs?

<details>
<summary>Answer</summary>

<Session guide="checkpoint-collections" run="q4" />

The order of the adaptors matters. `rev().enumerate()` reverses first and then counts the items it is handed, so `c` gets the number 0. `enumerate().rev()` attaches the positions first and then walks backwards, so `c` keeps 2. See [Position and backwards](/learn/for-collections/#position-and-backwards).

</details>

## Predict the error

### Question 5: an adder that cannot leave home

<Files guide="checkpoint-collections" dir="rust" files={["src/bin/q5.rs"]} />

Does it compile? If not, which error code, and what does the compiler suggest?

<details>
<summary>Answer</summary>

<Session guide="checkpoint-collections" run="q5" />

Without `move`, the closure borrows `n`, which belongs to `make_adder` and is gone when the function returns. The compiler suggests `move`, which makes the closure own its own `n`. See [Returning closures](/learn/closures/#returning-closures).

</details>

### Question 6: a collection with no name

<Files guide="checkpoint-collections" dir="rust" files={["src/bin/q6.rs"]} />

Does it compile? If not, which error code?

<details>
<summary>Answer</summary>

<Session guide="checkpoint-collections" run="q6" />

`collect` can build many kinds of collection, and nothing in the program says which one. The message points at `doubled` and says its type must be known at `.len()`, because `len` could mean any of them. `Vec<_>` on the `let` is enough, with `_` left for Rust to work out. See [Consumers: collect](/learn/iterators/#consumers-collect).

</details>

### Question 7: calling twice

<Files guide="checkpoint-collections" dir="rust" files={["src/bin/q7.rs"]} />

Does it compile? If not, which error code, and which trait does the message name?

<details>
<summary>Answer</summary>

<Session guide="checkpoint-collections" run="q7" />

The closure moves `name` out of itself when it runs (`drop(name)`), so it can run once; that is `FnOnce`. Calling it consumes it, so the second call uses a moved value. See [`Fn`, `FnMut` and `FnOnce`](/learn/closures/#fn-fnmut-and-fnonce).

</details>
